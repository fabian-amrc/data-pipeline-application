# Semantic Mapper

## Purpose

The Semantic Mapper provides a controlled interface for registering semantic mappings between physical data assets and ontology concepts.

It supports:

- Simple Python-based semantic mapping
- Expert RML/Turtle authoring
- Validation against an ontology/RDL
- Centralised storage of mappings
- Metadata projection to Unity Catalog

## Python Library

The client library is exposed by the `semantic_mapper` package in `src/semantic_mapper/__init__.py`. It gives application authors a small Python API while keeping RML/Turtle generation inside the Semantic Mapper API.

```python
from semantic_mapper import SemanticMapper

mapping = (
    SemanticMapper()
    .dataset("unity.default.example_dataset")
    .row_subject(rdf_class="dpa:Dataset")
    .subject_identifier(column="id", scheme="dpa:dataset-id")
    .storage(source_uri="s3a://delta/example-dataset", storage_location="s3://delta/example-dataset")
    .column("id", "INT", "Dataset identifier").literal(predicate="dpa:datasetId", datatype="xsd:integer")
    .column("name", "STRING", "Display name").literal(predicate="dpa:name")
    .column("age", "INT", "Example numeric attribute").literal(predicate="dpa:age", datatype="xsd:integer")
    .column("city", "STRING", "Example city attribute").classification(term="dpa:LocationAttribute")
    .register_and_project()
)
```

### Session

`SemanticMapper()` creates a mapper session using the standard in-cluster defaults: `manufacturing-rdl`, `spark-delta`, and the Semantic Mapper service URL. Override `ontology`, `profile`, or `base_url`, or set `SEMANTIC_MAPPER_ONTOLOGY`, `SEMANTIC_MAPPER_PROFILE`, or `SEMANTIC_MAPPER_API_URL` when needed.

### Dataset Mapping

`mapper.dataset(name: str)` begins a mapping definition for a dataset or table.

### Subject Definitions

`dataset.row_subject(...)` defines the ontology class represented by rows.

`dataset.subject_identifier(column="mmsi", scheme="sea:mmsi")` declares that a column contains the identifier for the row subject using a centrally registered identifier scheme. Users do not define URI templates directly.

### Physical Storage

`dataset.storage(source_uri="s3a://...", storage_location="s3://...")` records the physical source read by Spark and the optional Unity Catalog external table storage location.

### Column Definitions

`dataset.column(name: str, type_name: str = "STRING", comment: str = "")` selects a column for semantic mapping.

`column.literal(...)` maps a column to an RDF literal property.

`column.entity_reference(...)` maps a column to another entity using a registered identifier scheme.

`column.classification(...)` associates a column with a semantic category or classification.

`column.ignore()` explicitly marks a column as unmapped.

### Registration

`dataset.register()` submits the simple mapping definition to the Semantic Mapper API. The API generates RML/Turtle, validates it, stores it, and returns the mapping record.

`dataset.register_and_project()` performs the common SparkApplication flow: register, validate, activate the mapping graph, and project Unity Catalog metadata.

### Expert Mode

`mapper.register_rml(ttl: str)` registers raw RML/Turtle.

`mapper.register_rml_file(path: str)` registers RML/Turtle from a file.

## Identifier Schemes

Identifier schemes are centrally defined in `resources/ontology/identifier-schemes.json` and referenced by name.

Examples:

```python
dataset.subject_identifier(column="mmsi", scheme="sea:mmsi")

dataset.column("mmsi").entity_reference(
    scheme="sea:mmsi",
    predicate="sea:observedVessel",
)
```

The Python API never requires users to define URI templates directly.

## REST API

### Ontologies

- `GET /ontologies`
- `GET /ontologies/{ontology_id}`
- `GET /ontologies/{ontology_id}/prefixes`
- `GET /ontologies/{ontology_id}/terms/{term_id}`
- `GET /ontologies/{ontology_id}/identifier-schemes`
- `GET /ontologies/{ontology_id}/identifier-schemes/{scheme_id}`

### Mappings

- `POST /mappings`
- `GET /mappings/{mapping_id}`
- `GET /mappings`
- `DELETE /mappings/{mapping_id}`

### Mapping Lifecycle

- `POST /mappings/{mapping_id}/validate`
- `POST /mappings/{mapping_id}/activate`
- `POST /mappings/{mapping_id}/deprecate`

### RML

- `POST /mappings/rml`
- `GET /mappings/{mapping_id}/rml`
- `PUT /mappings/{mapping_id}/rml`

### Dataset Operations

- `POST /datasets/{dataset_id}/inspect`
- `GET /datasets/{dataset_id}/mappings`

### Metadata Projection

- `POST /projections/unity-catalog`
- `POST /mappings/{mapping_id}/project/unity-catalog`
- `GET /projection-jobs/{job_id}`

## Mapping Flow

### Simple Mode

```text
Python DSL
    ↓
POST /mappings
    ↓
RML generated by API
```

### Expert Mode

```text
RML/Turtle
    ↓
POST /mappings/rml
```

### Common Path

```text
Validation
    ↓
Mapping Storage
    ↓
Activation uploads active RML to the mappings graph
    ↓
Metadata Projection
```

## Runtime Storage

The API stores mapping records and RML documents under `SEMANTIC_MAPPER_STATE_DIR`, mounted at `/semantic-mapper/state` by the Kubernetes deployment. The local deployment uses a `ReadWriteOnce` PVC named `semantic-mapper-state`.
